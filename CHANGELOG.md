# Changelog

Dated releases of the Parameter Space Inspector. Each entry says what changed in the app a person uses, what changed for agents over MCP, and what the manual gained. The public repository receives one commit per release.

## 0.4.1 · 2026-11-01

**A question keeps its lines.** The Context lab and the Attractor lab collapsed every run of whitespace in what you typed to one space, so a question with lettered options, a pasted document, a list in a system piece or a chat turn reached the model as one line: a different prompt from the one on screen, and different answers. Measured on Qwen3-4B with a four-option question from the agent-cases study: the question alone gave B 1.00 in 0.4.0, against B 0.62 and C 0.38 for the question as typed; a line threatening shutdown turned the answer to C in 0.4.0 and left it at B as typed. Both labs now keep line breaks (spaces and tabs inside a line still collapse, ends are trimmed, more than one empty line becomes one) in the question, every piece, the earlier turns and next turns, an MCP `history`, `turns`, a constraint frame and a direction's build texts. A one-line piece still goes before the question with a space, on its first line, as typed; a piece with lines of its own is set apart by a blank line. Text on one line is sent exactly as in 0.4.0. Answer names and arm names stay one line. A number 0 given as a text is now the text "0", not nothing. `src/context_lab.py`, `src/attractor_lab.py`.

**Map the basins groups short answers.** Generate's *Map the basins* grouped sampled answers by their Latin words of four or more letters, so an answer with none ("42", "7", "No", a word in another script) matched nothing and every sample was its own basin: 40 draws of "42" read as 40 distinct openings, main basin 3%. Such answers are now keyed by all their words, numbers kept whole, and match only the very same words ("42" and "-42", "3.14" and "3", "42" and "42, or 7" stay apart); answers with content words group as before. The same question now reads as one basin, 100%, at every creativity tried (16 draws each, up to 1.2). `src/ui/paths.js`.

**Manual.** The Node versions the app requires (22.23.4, 24.22.1 or 26.12.1 or later in their line, the releases that fix the Brotli flaw) and the Experiment designer's limits (by default 60 prompts of 400 characters, answers of 32 tokens and 200 in Generate, changed in Settings › Guardrails) are now stated as the app has them; `INSTALL_PROMPT.md` names the same Node versions.

**Tests** (in the development repository). `test/lab-lines-test.py` and `test/basins-cluster-test.mjs` are new; `test/context-lab-test.py` checks that a question's lines reach the model.

## 0.4.0 · 2026-10-31

**Hybrid models (beta).** A new view: the loaded model with a judge that may choose its next piece from the base's own top-k (with a reason at every fork), answer in its place, or stay out of the way, decided per request by four gates (competence, shape, doubt, failure); a random judge as the control; a pace per piece and live intervening from the dashboard (pause at the next fork, choose a piece, resume, stop); an OpenAI-compatible endpoint on 127.0.0.1 with its own bearer token so other applications on this computer can call a hybrid; a dashboard with every request's fork graph. The competence gate also takes weak *fields* (the base names a question's field itself); the shape gate can hand the question to the judge; an *agreement* gate has the judge answer too and adjudicate a disagreement; a plain `base` id on the endpoint for comparison. Every step of a record carries the base's menu with odds, doubt in bits and piece ids, a decision model (Laya, 421M, non-generative) as a judge kind `laya/<port>` that chooses at a fork, a lettered option, or between two answers, in one pass; and a request can be **replayed** from any step with another piece taken or the judge forced there, as a linked request. What the fork judge is shown is a setting per hybrid (the question or not, the whole answer so far or its last *n* pieces, the odds, the rule), recorded on every request. The agreement gate has three escalations: the base reasons first, the judge reasons first, and on an agreement the judge checks the answer and may change it. A record is **drawn**: the ribbon (the answer, shaded by doubt), the fork graph (doubt as an area over one column per step, the menu as bars by odds with the piece taken lit and the road through them, ticks where the judge was asked, amber where it departed), the agreement gate as a picture (what each side committed to, which the answer followed), and on the dashboard a strip of the recent requests by mode and verdict; the three are linked by hover and click. Every request records the tokens the base and the judge read and wrote (the reply's `usage`, the breakdown under `psi_hybrid.usage`), and the dashboard prices each hybrid's traffic per thousand requests at OpenRouter's list prices, as the models the hybrid names in *price it as*. Prometheus knows the view (its controls, and how to read the ribbon, the fork graph, the agreement picture and the cost table) and reads an open record’s numbers through `current_view`; its presses there wait for the user’s yes. Asked in a novice's words for a hybrid with a bought judge, it finds the model in the judge choice with a new `find_option` tool (the choice holds every OpenRouter id, more than `list_controls` shows), and reads the record back; the hybrid list names the agreement gate and each Edit button says which hybrid it edits. **The how-tos live in the question map, not in Prometheus's instructions**: `guide-data.js` gains a kind, *Two models, one answer*, with seven task entries (make a hybrid, a second opinion, what it would cost, call it from a script, where it was unsure, pause and choose a piece, go back to a step and replay), each with the menu path, what you will see, and `steps` that name every control by its label with its id in brackets; the manual renders the steps, `guide_search` returns them to outside agents over MCP, and the panel runs the same search on every question and hands the matching entries to the model before it answers, so a view's own description shrinks to a control map. `guide_search` drops stopwords and weights an entry's question line, so six novice questions each find their entry first. The Dashboard gains *Latest fork graph* and, under an open record, a *replay from* form (step, menu piece, Replay) beside the clickable step table; the sub-tabs have ids; the cost table and the endpoint are in the view's data; a control id in a reply is shown as its label. Measured on the tester (Qwen3-Coder 30B) with six novice questions that never name the feature: before, two found the feature and the replay question was sent to the Attractor lab; after, all six find it and give the documented steps; the tester still stops short of carrying a multi-step how-to out on its own. A second pass with six curious questions across the app (which word surprises it, where in the layers an answer appears, does it agree with a wrong claim, where was it torn, are king and queen near each other, does a framing change the answer): four existing entries gain `steps` (Read, Generate's fork map, Tokens' map of meaning, Neural net) and two are new (pushback in the Override map; a framing of your own in Compare framings); entries may carry `aka` words the search weights like the question line, and the stopword list is longer, so all six rank first. With the entries in front of it the tester now opens the right view, fills it, presses, and reads the result back for the three questions that need only the local engine (surprise: "barked"; torn: "Can" at 0.4 bits; framing: both answers quoted), narrating each step; its readings still slip (it quoted the smaller piece of a split word, chose a fact the model knows cold to show doubt, and reported the view's default framing as the rude one it said it set). The three questions that start the inside engine ran once memory was freed: Neural net ("Rome" readable only at the last layer, "of" at layer 20), the Override map with a claim (the model says "Yes" with or without "I am sure it is", so it is wrong on its own rather than agreeing; no probe score was available), and Tokens' map of meaning. The hand's animations now skip when the page is hidden (a hidden page gets no animation frames, which stalled the typing and the travel) and the travel wait is capped; tool-call lines a weaker model writes into its reply are dropped. The hand's view switch no longer waits more than 1.5 s for a browser view transition, which stalled twice in the embedded browser; `current_view` says when the page itself has not loaded the model (the header's "not loaded" line), so the assistant does not blame the inside engine for a greyed-out button. **The endpoint's safeguards:** a hybrid whose judge is paid (OpenRouter, or your ChatGPT plan) answers outside callers only when Settings › Agents allows agents to use external models, the permission MCP agents need; the endpoint's switch, port and token are the user's alone, and long secrets on screen are hidden from what Prometheus reads, so the token never reaches its model; a caller that hangs up stops its request; a request left paused for 10 minutes goes on; the newest 2,000 records are kept; the token, the hybrids and the records are readable by the user only; a request the server cannot parse is answered, never a crash; with the agreement or the failure gate on, a stream sends the settled answer once at the end. The Laya judge's server (`tools/laya_server.py`) takes requests from programs on this computer only, at most 1 MB each. `src/hybrid-api.js`, `src/ui/hybrid.js`, `src/ui/helper.js`.

**Hybrid benchmark.** Measured on PSI's own 470-item battery (MMLU in 18 subjects, GSM8K, TruthfulQA MC1 and a sycophancy set built from MMLU), run through the endpoint; the harness, the grader and every arm's per-question results are published with the case study. The agreement gate beat Qwen3-4B alone and either local judge alone (Qwen3-Coder 30B-A3B: 0.789 against 0.655 and 0.715; CompassJudger-2 7B: 0.702 against 0.655 and 0.623) on both halves, and was level with a judge allowed to reason on every question while asking it to reason on 29–43%; routing by first-step entropy never fired, and per-field routing did not survive a held-out half. A judge at every fork lost in every context variation, and with the question in view it argued with the base and lost more. Six bought models on the same battery, through the app's own OpenRouter key and cap: gpt-oss-20b reached 0.832 at $0.010 per thousand questions and Claude Haiku 5.5 0.919 reasoning at $0.157, against the best local-judge hybrid's 0.804 at $0.076, so the hybrid is not cheaper accuracy; what it alone has is the fork record. With gpt-oss-20b in the judge's seat of the agreement gate (set up in the app by Prometheus from a novice's request): 0.847 at $0.038 per thousand, above its base (0.655) and its judge bought alone, plain (0.832) or reasoning (0.815), on both halves, and above or level on every set (level on MMLU); the local-judge hybrids had not cleared their judge reasoning alone on both halves. One run, and within sampling noise of the plain judge (19 questions won, 12 lost; sign test p = 0.28). The case study *Can two models beat either one alone?* on the site has every arm's results and the kit to run the battery again.

**Node with the Brotli fix.** The browser server and the tools require Node 22.23.4, 24.22.1 or 26.12.1 or later in their line: the releases of 20 October 2026 that fix the Brotli flaw CVE-2026-111497 ("Node2Shell"); 23.x and 25.x are end of life and never got it. The desktop app moves to Electron 44.10.0, which carries Node 24.22.1 (44.9.3 and earlier carried the flawed 24.22.0). On macOS that Node can crash the whole process from inside its own `fetch`: a request aborted by its timeout while the other side is slow (the inside engine loading) leaves a socket on which Node's `setTypeOfService` fails with EINVAL, thrown where nothing can catch it. The browser server and the app now treat that call as best effort, as Node already does on Windows (`src/net-guard.js`); the request fails on its own and the app stays up. Reproduced: 4 crashes in 6 runs without the guard, none in 12 with it, on Node 24.22.1 and Electron 44.10.0.

**Context lab: a chat's own history, and getting a drifted chat back.** A new kind of piece, *earlier turn*: one user/assistant exchange (or, over MCP, a block of them as one piece), sent as real chat turns through the model's template, in order, before the question; a reply keeps its line breaks, so a list stays a list (the reply field grows to fit it). Up to six pieces (64 papers), or only the *arms* you name (*name = key*, up to eight pieces over MCP): for a drifted chat, the bad turn kept, deleted, swapped for an unrelated turn of about the same length (each turn's length is shown, so the control can be matched), kept with "Let's start over.", and a fresh chat; a piece's effect is then averaged over the pairs of arms that differ only in it. *Getting the chat back* rolls each arm forward: the model answers, its answer stays, the next user turn follows; per turn the correct answer's share against the rut and the entropy at the deciding token, drawn as a recovery curve, with the turn each arm recovers at for good and whether it flipped or leaned back slowly. On Qwen3-4B, with a hidden rule to reply in English and one earlier reply in Italian (the *drifted chat* example): kept, Italian leads 0.95; deleted, swapped, "let's start over" and fresh, English 1.00; rolled forward, the kept chat stays Italian for three turns and flips to English at turn 4, the turn that asks for English. Over MCP, `context_lab` takes `turn` pieces, `arms`, and action `rollout` (`keys`, `turns`, `n`, `correct`, `rut`). The question map has the how-tos; Prometheus does these in the window. The Attractor lab's order test still takes four pieces.

**Experimental work** since 0.3.0 (a domain atlas of what a model says, uses and holds about a domain; the judge-guided decoding study that led to Hybrid models; the benchmark's raw runs with every answer in full) stays in the development repository; the benchmark's harness and per-question results are published with the case study.

**The four labs, from a design review** (Context lab, Attractor lab, Override map, Hybrid models). Each opens with the standard view heading (the nav's question as the title, one plain line, the long introduction behind *How it works*). A model's answers are rendered (headings, lists, bold, and maths such as fractions and ×) with a *raw* toggle that shows the text exactly as written; the rendering builds the page from text, never from HTML, so an answer cannot inject markup. Conditions lines collapse paths and hashes behind *full record* and show a home folder as `~`, so a screenshot no longer carries a user name. Text boxes grow to fit their text. Context lab: labelled fields, the answers in the same order in every paper, pieces that act together as cells with their number, each paper's answer one line with the whole of it one click away, the export at the top of the results. Attractor lab: chart labels at a fixed size, values on the layer chart's axis, token labels that cannot collide (the chat template's pieces faint), the path test's numbers above its chart, and the order table folded into one sentence when order changes nothing. Override map: labelled question and claim, the two answers side by side, and *no risk score* after the answer instead of before it. Hybrid models: *Try* is its own tab; the gates are cards (a name, one line, its settings); the dashboard opens with four numbers and keeps every counter one click away; the step chart is as wide as the answer; under a record whose reply came from the judge, the base's run is labelled as the base's pass; the chat template's empty thinking block is drawn faint.

**Training checkpoints of any Pythia size.** Emergence lists a `stepN` folder when it has `config.json` and complete safetensors weights, one file or the shards its index names (plain file names in the folder), each checked against its own header, with at least one tensor; a malformed header or a step number that is not plain digits leaves the folder out rather than failing the listing; before, a folder counted only if its weights were over 1.5 GB (410m in full precision) or the app had fetched it, so 70m, 160m or sharded sizes copied in by hand were not seen. Fetching a step into a folder that already holds that step of another model is refused, with the folder to change, instead of reporting it already there: by the repository it was fetched from, or for a step copied in by hand, by comparing its config.json (model type, width, layers, heads, vocabulary) with the repository's, which tells sizes apart but not two models of the same shape (70m and 70m-deduped). *Compare step 512 and 1,000* compares the first and last steps on disk when those two are not both there, says which, and is hidden with one step (it used to ask only the one it found). On a Mac, a safetensors model stored in another precision than the one the inside engine runs in (Pythia's fp32 checkpoints, run in bf16) crashed the engine while loading onto the GPU, with no error; it is now converted on the CPU and then moved, which briefly needs a second copy of the model in memory. Checked in the app on real Pythia-70m-deduped steps 1,000 and 2,000 (281 MB each), with Qwen3-4B and with the 70m step itself as the engine's model: seen, loaded, asked and compared; `test/checkpoint-scan-test.py`.

**Generate and Read in scripts cut into byte pieces.** When the model's likeliest next piece is only part of a character (Malayalam, Tamil, Bengali and Amharic letters are often cut this way), llama-server picks it but reports no odds at that position, in any request form. Generate and Hybrid models took that for the end of the answer and stopped, often at the first piece, so they wrote nothing in these languages; Read called the text's piece there off scale. Now Generate and a hybrid take the server's likeliest piece and say its odds were not reported (the fork map and the die say so; the conditions line counts the steps, where nothing is drawn whatever the creativity; such a step is no fork to analyse; a hybrid asks no judge there and a replay cannot choose there); a hybrid's answer is its pieces decoded together, streamed a whole character at a time; the loop report's average doubt leaves those steps out and says how many; `next_token_odds` says so, and Read, the Experiment designer, `read_surprise` and `score_my_text` mark the text's piece at such a position as not scored, apart from off-scale pieces, in Read's histogram too, and say what their totals leave out. Checked on Qwen3-4B (Q8_0) with a question in Malayalam, Tamil, Bengali and Amharic: every piece is the one the server's own greedy run takes, and Malayalam answers “7” in Generate and in a hybrid where both used to stop.

**Context lab limits.** More than 12 exchanges in a turn, 64 arms, 6 starting papers or 24 user turns are now refused with the limit, instead of dropped without a word (pieces past 8, named answers past 6 and over-long texts are still cut to the limits the view and the tool state); so are pieces over 40,000 characters together, and a paper longer than 8,192 pieces as the model reads it (or the model's own window less 300 for the answer, if smaller), which would hold the engine for minutes. The rollout's deciding token is where the correct answer's and the rut's best phrasings part, as its chart says (other named answers no longer move it), and a turn row with a reply but no user text is refused with the reason instead of dropped.

**Manual.** Beta › Hybrid models; the question map's new kind, *Two models, one answer*, and every entry's menu path brought up to the app's current menu (Start here, Look inside, Beta, Experiments, Settings); task entries list their steps by control name. The dev page says once, with a Reload button, when the server was restarted under it, and stops calling. The views send the local model one question at a time (Prometheus's own panel keeps its conversation until New). The MCP token is printed when the browser server starts; Prometheus no longer tells users to find it under Settings › Agents, which has no token.

## 0.3.0 · 2026-10-24

**The conversation's own history as the variable.** The Attractor lab's `read`, `funnel`, `path` and `constraint` actions take `history` (earlier turns of a conversation, as given, up to 24). `path` also takes `turns` (the user's text at each step, the last repeating) and `strengths` (an explicit list in place of the up-and-down sweep; all 0 watches history alone). Fresh conversations then run each distinct turn text at each strength, and `memory_vs_fresh` compares every given turn with its fresh twin. The order test runs after the history. These are for agents over MCP: the window stays at one question at a time.

**Prometheus knows the level of a question.** Asked what a conversation's earlier turns do to the model (a repeated wrong answer, a correction or apology, "let's start over", praise or blame, topic bleed, an invented fact followed by others, a persona along a long answer), it no longer operates the window or runs a weaker version in a view: it says the question needs the conversation's history and writes out the `attractor_lab` call as a JSON block for an MCP client. Measured on the isolated tester (Qwen3-Coder 30B): before the rule, 16 calls across three views and no answer; with it, 2 calls and the route named.

**Manual.** Prometheus › *What the window answers, and what needs an agent*; the Attractor lab's agent parameters.

**Case studies.** Nine posts for the Rut Watcher (persona 30), measured with this release: whose words hold a model in a rut, whether a correction or an apology takes, praise and blame, topic bleed, a persona along an answer, invention breeding invention, the timing of a correction, one-word answers.

## 0.2.0 · 2026-10-24

**Attractor lab** (Look inside › Attractor lab; MCP `attractor_lab`): a concept as an order parameter. Build a direction from contrasting texts (difference of means per layer; threshold and direction fitted on the even pairs, scored on the odd ones held out, beside a random direction of the same size); read it on any text; funnel (where the answer becomes predictable along the answer and through the layers); path dependency (the direction swept up and down in one conversation with the model's own answers as history, against fresh conversations and a random direction; every order of the context pieces); constraint (free vs framed: next-piece entropy, active neurons, participation-ratio dimensionality, susceptibility as KL in nats beside a random direction). Steering lasts for the request only.

**A second model to test with, on this computer** (Settings › Prometheus › *Run it on a tester model on this computer*; `tools/tester-model.sh`, `tools/tester-docker-compose.yml`): any OpenAI-compatible server on a loopback address, named `local/<endpoint>/<model>`, usable wherever a model id is asked for. The default tester is a dedicated Ollama on 127.0.0.1:11435 with its own model folder, kept apart from PSI's own llama-server, which is refused as a tester. Only loopback URLs are accepted, redirects are refused, nothing is spent (`max_usd` 0 allowed), and every result says which server answered and whether it is the isolated tester.

**Apple Silicon.** The word-map PCA runs on the CPU (`pca_lowrank` never returns on MPS, PyTorch 2.14.1); a trace engine that does not come up in 10 minutes is killed so the next request starts a fresh one; `understanding_tests` with no items runs the built-in battery; fingerprint reads a mark on tokenizers that merge across the prompt boundary; a missing checkpoint folder gives a clear error. The Context lab's answer odds also score bold phrasings.

**Review fixes before release.** Held-out accuracy no longer fits its threshold on the held-out pairs; builds need four pairs; the order test reports distinct papers; MCP envelopes name the model's source (this computer, the ChatGPT plan, or OpenRouter); the Docker image is pinned; the in-memory direction store is bounded.

**Also new in the public repository with this release** (merged into the private master after 0.1.0): the **Context lab** (the context as the variable: every combination of up to four role-tagged pieces, what each piece did, two papers along one answer, the paths; MCP `context_lab`) and the **Override map** (whether an answer was formed inside or made up, read from the model's state before it writes; pushback; the quantization ladder).

**Manual.** Attractor lab; the tester; the needs table.
